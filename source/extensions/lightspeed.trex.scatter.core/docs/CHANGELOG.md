# Changelog
The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.0.0/).

## [1.0.0]
### Added
- Created the scatter brush core: brush settings and presets, seeded disk sampling with falloff and padding, a numpy mesh-surface cache for CPU projection and normals, HdRemix and CPU surface pickers, Remix prototype/instance target resolution, undoable stroke and flood commands, the brush controller, and automatic assignment of each asset's ingested texture set (albedo, normal with its encoding, roughness, height, metallic and emissive) to the placements it paints. Dragging one end of a low/high setting pair past the other carries the other end along instead of refusing the edit
- Placement size is a world-space quantity like the brush radius, padding and spacing: the parent instance's scale is divided out of both the authored scale and the vertical offset, so a placement comes out the same size wherever it is painted. Each asset's `metersPerUnit` and natural size are read when it joins the palette, and the new Absolute Size scale mode uses them to give every placement a height in stage units measured along the asset's up axis; an asset that cannot be measured keeps its own size. Textures and measurements are now also resolved at the start of a paint stroke, so a palette restored from disk no longer paints without them when the Scatter window was never opened
- An asset that authors no `upAxis` is now taken as Y-up, matching USD's own fallback, instead of Z-up which skipped the up-axis correction and scattered it on its side. A palette entry whose up axis disagrees with the one its file authors is reported once per stroke, because that mismatch is otherwise silent and looks like a brush fault
- A stroke now counts the prims it adds to the rendered stage, not just the placements it authors: a placement under a prototype renders once per instance of that prototype's hash, so `StrokeSession.rendered_prims` multiplies each stamp by the target's instance count. The new `prim_budget` setting and `prim_budget_status` classify that total so a brush can report an expensive stroke while it is being painted
- Placements now record the surface they were composed from, their own random key and a checksum of the transform the brush gave them, so a settings change can recompose scatter that already exists instead of only affecting the next stroke. `reapply.py` resolves the selection into the placements an edit may write to (selected placements or a scatter container win outright, otherwise the container of the current preset on each selected prototype), recomposes them through the same function that painted them, and commits one `ScatterReapplyCommand` per edit. A placement whose transform no longer matches its checksum was moved by hand and is left alone; one painted before the brush recorded surfaces is projected back onto its mesh and reported, because its original random draws cannot be recovered. Only placement, scale and seed settings re-apply: the brush and density settings decide where stamps land, which depends on the mouse path a stroke followed and is not recorded
- Added `move.py`, which moves the placements a selection resolves to by a world-space delta and settles each one back onto the capture mesh it lands on. A move consults no brush setting but Conform to Surface: it transforms the transform a placement already carries, so dragging a patch can never also resize or re-rotate it from whatever happens to be in the Scatter window. The surface each placement records moves with it, so a settings change afterwards recomposes it where it now sits, and placements accumulate `remixScatterYaw` so a recomposition also keeps a turn the gizmo applied. A placement the user moved by hand travels with its patch and stays theirs, because `PlacementTransform` now carries whether a write marks the placement as the brush's again; it also carries the surface and the turn, so one `ScatterReapplyCommand` undoes a move whole
- The move gizmo's rotate rings now aim a patch instead of carrying it around. A turn leaves every placement's position and recorded surface exactly as they are and changes only the way it points, so the rings behave like a trackball on the patch. Previously a turn rotated the placements about the gizmo handle and then re-planted them, which on any ring but the one about the surface normal swung the far side of a patch up into the air and dropped it elsewhere on the mesh; and because re-planting composes exactly the inverse of the tilt just dragged, no tilt survived it either, so those rings appeared to do nothing at all
- A slide now settles a placement onto the surface normal only when Conform to Surface is on, so a patch of assets the brush was told to stand straight up is no longer tipped over by the ground it is slid across
- Changing a palette entry's up axis or its measurements now re-applies to the selected placements live, the way moving a slider does; correcting an asset scattered on its side used to leave the patch in front of the user unchanged until they happened to nudge a brush setting. Adding, removing, re-weighting or re-texturing an entry does not re-apply, because none of those change a placement that is already painted
- A turn now carries the rings' rotation into the space of the instance that parents the placements before it is applied. A capture's instances stand at whatever angle the game left them at, while a placement's transform and the surface it recorded are held in that instance's space, so a ring used to aim the patch about a different axis than the one being dragged: on a tilted instance the ring about the stage up axis left the patch untouched while the other two tipped it flat instead of spinning it where it stands
- A placement now records the whole turn it has been given, not just its yaw, so a patch tipped over by the rotate rings or by the Scatter window's Turn fields stays tipped when a settings change recomposes it instead of standing straight back up on its surface. The yaw it already recorded keeps its old meaning and its old place in the composition, so scatter painted before this composes to exactly what it always did. The turn a patch has been given since it was selected is held on the controller, which is what lets the viewport gizmo and the Scatter window show and drive the same turn without either owning the other, and `ScopeDragSession` now holds the drag lifecycle both of them use so a turn typed into a field is one undo step exactly as a drag of a ring is
- A move no longer uses a default-constructed `Gf.Rotation` to stand for no rotation. That constructor leaves its angle uninitialized, so a slide that should not have turned anything occasionally turned a patch by whatever happened to be in that memory, tipping it over; nearly always the value was harmless, which is what made it look intermittent
- The stroke just painted is now the preview: `ScatterBrushController.begin_preview` makes the stroke on top of the undo stack what live edits change, ahead of the selection, until anything else is executed, undone or redone, the selection changes or the stage closes. Edits of the preview add no undo step of their own; `ScatterStrokeCommand` now snapshots a stroke as it stands when it is undone and restores that snapshot on redo, so one undo removes the stroke with everything done to it while the brush settings stay as they were left
- Added `base_rotation_x`, `base_rotation_y` and `base_rotation_z`, re-appliable brush settings that turn every placement about its own root before its random rotation, so an asset that comes out lying down is stood up for every stroke from then on
- Added `max_surface_angle`, which skips stamp and flood candidates on surfaces steeper than that from the stage up axis. A stamp snaps each candidate onto the closest surface within the brush radius, so near walls and ledges candidates landed on the side of them and, conformed to it, stood sideways; on the demo capture that was more than half of every stamp. The default of 180 keeps every candidate
- `get_reapply_driver` now provides one live-edit driver per USD context, shared by the Scatter window and the viewport gizmo; `hold` and `release` keep one edit open across a drag that changes several settings
- Live edits and gizmo drags are much cheaper. An edit reads its placements once and only composes and writes them at each step, replaying each placement's random draws instead of rebuilding its generator; a drag writes each step once instead of rewinding the patch first, and settles a slide with one batched query bounded by how far the slide went. Closest-point queries over many points now group them by neighbourhood before narrowing the triangles. An erase stroke reads each prototype's placements once instead of at every stamp, a stroke with no padding no longer reads the placements already on the stage, and removing, snapshotting or restoring every placement of a container is one edit. Measured on 2,000 placements over a 9,800-triangle mesh with no renderer attached: a live-edit step went from about 880 ms to about 150 ms and a gizmo slide frame from about 6.2 s to about 0.3 s. A gizmo drag of more than `LIVE_EDIT_SOFT_LIMIT` placements now moves the patch once when it ends
- Closest-point queries no longer pair every candidate with every triangle within the brush radius. The search starts at a reach about the size of one triangle and widens only for candidates it has not settled, each candidate tests only the blocks of a new Z-ordered triangle index that its own box overlaps, pairs that cannot hold the nearest triangle are dropped by cheap distance bounds, and pairs are reduced a slice at a time. Results are unchanged, exactly as an exhaustive search gives them; measured over an 80,000-triangle mesh, 500 candidates at a radius of 300 went from 8.4 s and 6 GB of temporaries to 24 ms and under 1 MB, and a single hover query at a radius of 1000 from 28 ms to 1 ms. Ray casts test the same blocks first instead of every triangle
- A paint or erase stroke now stops stamping once 8 ms of a frame are spent and carries on from its last stamp on the next update or `StrokeSession.resume`, so heavy settings make the brush trail the cursor instead of freezing the application. The stamps are the ones an unpaced walk makes and none is dropped: ending the stroke stamps whatever it is still behind on, and a failure while doing so still commits everything authored. The stamp centres of a segment are projected in one batched query (`MeshSurfaceCache.closest_samples`) instead of one query per stamp
- Resolving a hover pick no longer walks every instance on the stage: the instances of every hash are read once per stage and re-read only after a resync that can add, remove or rename one, which took a hover pick on a capture of 10,000 instances from 16 ms to under 0.1 ms. A hit on a capture mesh is used directly instead of being looked for again by bounding box, so a neighbouring mesh whose bounds also contain the point is no longer sampled instead
- `PaddingIndex` cells now follow the padding instead of being at least one unit, and a check compares plain floats, so a padding check costs a few microseconds however fine the padding is
- A stroke whose authoring fails part way now keeps the placements that were authored in its undo step instead of leaving them in the layer with nothing to remove them
- The CPU picker culls meshes by their stage bounds before building their triangles and skips painted placements, so a pick no longer rebuilds the geometry of every visible mesh or walks every blade of a painted field
- The brush now paints on the selected mesh with every asset standing straight up by default: `apply_to` defaults to `SELECTED` and `conform_to_surface` to off. Without conform, an asset stands on world up as its parent instance sees it, so a rotated capture instance no longer tilts what is painted on it. Stamp and flood normals are turned to face the side being painted (the camera for a stroke through the new `StrokeSession` `view_point`, the stage up axis for a flood): captured meshes are often wound the other way round, and on one Tomb Raider Anniversary capture every recorded normal pointed into the ground, which hung conformed assets upside down under the floor and made every floor fail Max Surface Angle. While the brush paints on the selection, a selected mesh is no longer a live-edit scope, so a setting changed between strokes does not rewrite everything already painted on it. Added `selected_capture_meshes`, `ScatterBrushController.reset_settings`, and an up-axis mismatch message that names where to fix it. Brush settings now carry a `settings_version`; settings and presets saved before version 2 adopt Apply To Selected and Conform off once when read back, because otherwise a brush persisted from an earlier session kept painting on whatever was under the cursor and ignored the selected ground
- Painted scatter is now instanced: a PLACE stroke with `instance_strokes` on, the new default, merges every other loose placement of its layer into one `UsdGeom.PointInstancer` per patch (`instanced_<slug>`, beside its `scatter_<slug>` container) as part of its own undo step, and a flood merges itself too, so the runtime draws each asset from one copy of its geometry with GPU distance culling instead of processing one replacement per blade. The stroke just painted stays loose, so it is still the preview. Each distinct asset and texture-override set becomes one prototype with an empty op order, entries keep every value their placement recorded so `split_instancers` and `ScatterSplitCommand` give the placements back exactly, and `ScatterInstanceCommand` merges on demand. Erase and padding reach instanced entries (`InstancedEraser`, `instanced_pool`, `instanced_points`), selecting instanced scatter resolves to no live-edit scope, and `scene_scatter_cost` counts instanced placements. Because HdRemix draws a point instancer's prototypes once and none of its instances, `InstancerViewportPreview` keeps a stand-in of every scatter instancer in the session layer, which is never saved, so the toolkit viewport shows what the game will draw. On the Tomb Raider Anniversary project, Instance All merged 1,450 placements in about 0.4 s, the edited layer went from 2.1 MB to 0.6 MB, the viewport rendered the same as before, and undo restored the layer byte for byte
- Added scatter groups for the REST API and its MCP tools: `ScatterGroupsCore` lists the captured surfaces with PNG previews and numbered contact sheets of their textures, and creates, retunes and removes named floods of ingested assets with an amount (light, medium, heavy) and tuning, each in one undo step and recorded in the layer they author. `flood_targets` now holds the flood loop the brush and the groups share, and `brush_spec_paths`, `ScatterRemoveBrushCommand` and `ScatterSetGroupRecordCommand` remove a group's scatter and keep its record
- A stroke and a flood now stop at five times `prim_budget` rendered prims (`stroke_prim_limit`), counted once per instance of the prototype painted on: `StrokeSession` trims the stamp that would pass the limit and reports `limit_reached`, skips a mesh with more instances than it has room left for and notes it in `blocked_prototypes` without ending the stroke, and `flood_targets` draws a few samples for each placement it has room for, keeps what fits and returns a `FloodOutcome` saying what it placed, what that renders and whether the limit held it back, which a scatter group records as `prim_limited`. Ending a stroke that fell behind the cursor now catches up for at most one second and reports the rest through `cut_short`, where it used to freeze the application until the whole backlog was stamped; an error while catching up is reported through `failed` and still commits what was painted. A flood also keeps its padding from instanced scatter, which it used to ignore
- Padding and erase are now measured at the surface point a placement was painted on rather than where it stands, so a vertical offset no longer lets a second stroke ignore the padding or puts a raised placement out of the eraser's reach. A stroke that crosses between instances of one mesh keeps its padding on each of them, and an erase stroke reads each instance's placements where they stand on that instance
- A fractional `density` now draws its extra candidate with the probability of its fraction, so 0.5 is one candidate every other stamp as a flood already treated it; it used to be rounded up, so every density below 1 painted as densely as 1 and the slider could not thin a stroke any further. On a Y-up stage the second tilt range now leans an asset over about Z instead of spinning it about its own up axis, and a move of a placement with no surface in reach falls back to the stage up axis instead of always Z
- Removing placements no longer costs the size of the container for each one removed when few children stay: the container is rebuilt from those in one copy (5,000 out of 10,000 went from 0.85 s to about 0.25 s by the per-child rates measured), `author_placements` no longer searches a container's children for every placement it authors, erased instancer entries are written once per frame instead of once per stamp, and the viewport stand-in finds what changed with array operations and deactivates stand-ins instead of deleting them one by one. The mesh cache keeps a mesh's bounds after evicting its geometry, so painting on a selection of more meshes than the cache holds no longer rebuilds each of them on every hover, and it no longer compares every cached mesh with every changed path
- Removing the last scatter under a mesh now also removes the empty `over` specs authoring it had created, so painting on a mesh the mod never touched and undoing it leaves the layer as it was. A face count that is negative or absurdly large no longer makes building a mesh's geometry fail or allocate gigabytes, and invalidating the root path now clears the mesh cache as its contract says
- Reset to Defaults and applying a preset keep the Edit Selection Live toggle as it is, and Reset keeps the preset name, so neither starts rewriting the selected scatter or leaves the preset list pointing at a preset that was not loaded. `PresetStore.stored_name` and `ScatterBrushController.stored_preset_name` say which stored preset a save would overwrite, including one whose name differs only in case on a file system that ignores it. Undo and redo reset the Turn fields the selection was given and notify `subscribe_history_stepped`. `ScatterBrushController.post_stroke_summary` posts what a stroke or a flood did behind the up-axis mismatch reported when it started, so the summary does not take that warning off the status line. A palette edit that re-applies to the selection now commits its undo step at once instead of leaving the edit open, and `ReapplyDriver.follow_settings` is public so the Scatter window can open the edit before it finishes it, whichever of the two the controller notifies first
