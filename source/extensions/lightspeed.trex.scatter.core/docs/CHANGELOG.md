# Changelog
The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.0.0/).

## [1.0.0]
### Added
- Created the scatter brush core: brush settings and presets, seeded disk sampling with falloff and padding, a numpy mesh-surface cache for CPU projection and normals, HdRemix and CPU surface pickers, Remix prototype/instance target resolution, undoable stroke and flood commands, the brush controller, and automatic assignment of each asset's ingested texture set (albedo, normal with its encoding, roughness, height, metallic and emissive) to the placements it paints. Dragging one end of a low/high setting pair past the other carries the other end along instead of refusing the edit
- Placement size is a world-space quantity like the brush radius, padding and spacing: the parent instance's scale is divided out of both the authored scale and the vertical offset, so a placement comes out the same size wherever it is painted. Each asset's `metersPerUnit` and natural size are read when it joins the palette, and the new Absolute Size scale mode uses them to give every placement a height in stage units measured along the asset's up axis; an asset that cannot be measured keeps its own size. Textures and measurements are now also resolved at the start of a paint stroke, so a palette restored from disk no longer paints without them when the Scatter window was never opened
- An asset that authors no `upAxis` is now taken as Y-up, matching USD's own fallback, instead of Z-up which skipped the up-axis correction and scattered it on its side. A palette entry whose up axis disagrees with the one its file authors is reported once per stroke, because that mismatch is otherwise silent and looks like a brush fault
- A stroke now counts the prims it adds to the rendered stage, not just the placements it authors: a placement under a prototype renders once per instance of that prototype's hash, so `StrokeSession.rendered_prims` multiplies each stamp by the target's instance count. The new `prim_budget` setting and `prim_budget_status` classify that total so a brush can report an expensive stroke while it is being painted; the budget never stops or trims a stroke
- Placements now record the surface they were composed from, their own random key and a checksum of the transform the brush gave them, so a settings change can recompose scatter that already exists instead of only affecting the next stroke. `reapply.py` resolves the selection into the placements an edit may write to (selected placements or a scatter container win outright, otherwise the container of the current preset on each selected prototype), recomposes them through the same function that painted them, and commits one `ScatterReapplyCommand` per edit. A placement whose transform no longer matches its checksum was moved by hand and is left alone; one painted before the brush recorded surfaces is projected back onto its mesh and reported, because its original random draws cannot be recovered. Only placement, scale and seed settings re-apply: the brush and density settings decide where stamps land, which depends on the mouse path a stroke followed and is not recorded
- Added `move.py`, which moves the placements a selection resolves to by a world-space delta and settles each one back onto the capture mesh it lands on. A move consults no brush setting but Conform to Surface: it transforms the transform a placement already carries, so dragging a patch can never also resize or re-rotate it from whatever happens to be in the Scatter window. The surface each placement records moves with it, so a settings change afterwards recomposes it where it now sits, and placements accumulate `remixScatterYaw` so a recomposition also keeps a turn the gizmo applied. A placement the user moved by hand travels with its patch and stays theirs, because `PlacementTransform` now carries whether a write marks the placement as the brush's again; it also carries the surface and the turn, so one `ScatterReapplyCommand` undoes a move whole
- The move gizmo's rotate rings now aim a patch instead of carrying it around. A turn leaves every placement's position and recorded surface exactly as they are and changes only the way it points, so the rings behave like a trackball on the patch. Previously a turn rotated the placements about the gizmo handle and then re-planted them, which on any ring but the one about the surface normal swung the far side of a patch up into the air and dropped it elsewhere on the mesh; and because re-planting composes exactly the inverse of the tilt just dragged, no tilt survived it either, so those rings appeared to do nothing at all
- A slide now settles a placement onto the surface normal only when Conform to Surface is on, so a patch of assets the brush was told to stand straight up is no longer tipped over by the ground it is slid across
- Changing a palette entry's up axis or its measurements now re-applies to the selected placements live, the way moving a slider does; correcting an asset scattered on its side used to leave the patch in front of the user unchanged until they happened to nudge a brush setting. Adding, removing, re-weighting or re-texturing an entry does not re-apply, because none of those change a placement that is already painted
- A turn now carries the rings' rotation into the space of the instance that parents the placements before it is applied. A capture's instances stand at whatever angle the game left them at, while a placement's transform and the surface it recorded are held in that instance's space, so a ring used to aim the patch about a different axis than the one being dragged: on a tilted instance the ring about the stage up axis left the patch untouched while the other two tipped it flat instead of spinning it where it stands
- A placement now records the whole turn it has been given, not just its yaw, so a patch tipped over by the rotate rings or by the Scatter window's Turn fields stays tipped when a settings change recomposes it instead of standing straight back up on its surface. The yaw it already recorded keeps its old meaning and its old place in the composition, so scatter painted before this composes to exactly what it always did. The turn a patch has been given since it was selected is held on the controller, which is what lets the viewport gizmo and the Scatter window show and drive the same turn without either owning the other, and `ScopeDragSession` now holds the drag lifecycle both of them use so a turn typed into a field is one undo step exactly as a drag of a ring is
- A move no longer uses a default-constructed `Gf.Rotation` to stand for no rotation. That constructor leaves its angle uninitialized, so a slide that should not have turned anything occasionally turned a patch by whatever happened to be in that memory, tipping it over; nearly always the value was harmless, which is what made it look intermittent
